# #641 일괄 머지 전에 누적 충돌을 검증한다

## 잘못된 가정과 확인 근거

10개 PR이 같은 `develop` 기준에서 각각 `MERGEABLE`이고 CI가 성공하면 일괄 머지를 진행할 수 있다고 판단했다. 그러나 #643을 먼저 머지한 뒤 #642의 `WIP.md`와 `CHANGELOG.md`에서 동일 위치의 추가 항목이 충돌했다. `git merge-tree --write-tree origin/develop fix/issue-631-falkordb-label`로 문서 충돌을 재현했다.

개별 PR의 검증은 각 변경과 기존 base의 조합에 대한 증거이며, 모든 변경을 누적한 결과의 증거가 아니다. 승인 요청 전에 누적 충돌을 확인하지 않아 승인 후 head를 다시 준비해야 했다.

## 조정과 검증

- 남은 PR을 #631 → #633 → #634 → #635 → #636 → #637 → #638 → #639 → #640 순으로 누적했다. PR의 대상은 `develop`을 유지한다.
- 공통 문서의 이슈별 항목을 보존했다. #637의 CSV 한국어 README 충돌도 #633의 `None` 설명과 classpath 사용법을 함께 남겼다.
- 이전 head와 새 parent 기준의 코드·테스트 변경을 비교해 각 이슈의 고유 변경이 유지되는지 확인했다. 기존 SHA를 보존하고 원격 갱신에는 해당 SHA를 명시한 `--force-with-lease`를 사용했다.
- 변경된 head의 독립 검토와 CI는 별도 증거로 수집한다. 기존 head의 CI나 승인을 새 head의 검증·승인으로 표시하지 않는다. 이 기록 시점에는 후속 PR의 머지가 대기 중이다.

## 다음 작업의 예방 규칙

일괄 머지 승인을 요청하기 전에 실제 머지 순서로 누적 tree를 구성하고 `git merge-tree` 또는 격리 브랜치에서 충돌을 검사한다. 공통 문서의 추가·수정과 여러 이슈가 함께 바꾸는 호출자·테스트를 포함한다. 충돌을 조정한 최종 head에서 CI와 필요한 독립 검토를 마친 뒤 정확한 SHA 목록으로 승인받는다. 코드 충돌에는 문서용 union 해법을 적용하지 않는다.
